# Owner-imported conversation transcripts — 19 November 2026

## Confirmed gap and implementation

The existing sales-review path reads selected CRM notes, qualification observations and stage history through `get_pipeline`. Notes are explicitly not a verified transcript. There was no permissioned transcript import or a way for that tool to inspect actual conversation text. Book 11's discovery/evidence guidance and the execution-engine boundaries informed this extension. Repository and installed Next client-component guidance were read before editing.

Owners/editors can open **Customers → Customer progress → a deal → Conversation transcripts**, paste text or import a UTF-8 `.txt` file, inspect/redact it, add a title/source and optional conversation date, and explicitly attest permission with a description of its basis. There is no default consent, assumed date, automatic upload on file selection, audio capture or model call. The imported text is labeled owner-supplied rather than authenticated testimony.

- Up to six immutable transcripts per deal, each 20–16,000 UTF-16 code units after trimming surrounding whitespace. File selection is limited to 64 KB; null-containing or oversized content is rejected. Duplicate exact text cannot inflate the evidence. No automatic truncation or replacement of another transcript.
- Transcript bodies live in an indexed tenant/deal table, separate from ordinary deal records. The deal retains a monotonic transcript revision. This avoids pulling long conversations into every pipeline or planning query.
- The owner reads explicit text pages. The existing `get_pipeline` tool now supports `view=transcripts`, lists source metadata and reads a selected transcript by index against the exact deal version. Pages contain at most 1,500 Unicode code points, preserving supplementary characters; subsequent offsets and the version are validated. Any changed record requires a fresh review. Returned tool schemas preserve the owner-supplied distinction and coverage, and exclude internal author identifiers.
- The existing **Review next step** action prepares an editable question that includes transcripts; it never submits it. The actual assistant instructions require reading relevant text pages before quoting or evaluating a conversation and disclosing unread portions, uncertain speakers and unknown dates. Transcript text cannot grant permission, become measured demand or justify an inferred purchase probability. Existing tool-output untrusted-data handling and consequential-action approval remain in force.
- Viewer access is read-only; imports/removals require the existing edit permission and independently verify the deal's tenant. Imports and removals use expected revisions. Removal is explicit and audited without copying transcript text into the audit log. Deleting a deal removes its complete supported transcript set atomically; an oversized unexpected set refuses partial deletion.
- Workspace export includes the newest 20 transcripts and explicitly reports additional coverage. Full workspace purge includes transcript rows. Existing chat/export copies, if the owner has separately created them, are not erased by removing the source transcript. Contact erasure does not infer a link to all free-text CRM conversations; remove the relevant transcript/deal when that is part of a privacy request.

The original prototype embedded text inside deal rows. Review identified the risk to existing bounded pipeline reads, so the final implementation uses separate storage. Only two synthetic local demo records had prototype fields; those fields were cleared in the guarded loopback fixture database with all deal identities preserved. No hosted data or user records were migrated.

## Remaining limits

This closes manual transcript intake and selected-record evidence retrieval. It does not implement call recording, speech transcription, automatic speaker attribution, conversation scoring, general transcript aggregation into customer-voice themes, or continuous call intelligence. Real conversation accuracy, representativeness and live model analysis quality remain unverified. The assistant's existing turn/output limits can prevent reviewing all saved text in one run; it must disclose partial coverage. Permission is the owner's attestation, not a legal or factual verification. Paid calls remain paused; runtime model, routes and evaluation budget are unchanged.
